Block 1 · What is JavaScript?

A language built in ten days

JavaScript began life in 1995 at Netscape, written by Brendan Eich in about ten days. It went through a few names before the one that stuck.

A short history

  • First prototype was code-named Mocha, then briefly renamed LiveScript
  • Renamed JavaScript for marketing reasons, to ride the popularity of Java — the two languages are otherwise unrelated
  • Standardized in 1997 as ECMAScript, so "JavaScript" and "ECMAScript" mostly mean the same thing today
  • Now one of the most widely used programming languages, running in nearly every web browser

What is it used for?

  • Making web pages interactive — form validation, animations, dynamic content
  • Building full front-end applications (the logic behind buttons, menus, live updates)
  • Server-side programming, via Node.js
  • Mobile apps, desktop apps, and even small embedded devices

Block 1 · What is JavaScript?

Two places you'll run it today

JavaScript needs an "engine" to execute it. Today we'll use two: your browser, and (optionally) Node.js on your machine.

In the browser

Every browser (Chrome, Firefox, Safari, Edge) has a built-in JavaScript engine. Code can live in:

  • A <script> tag inside an HTML page
  • An external .js file linked from HTML
  • The browser's developer console, for quick experiments

On the server, with Node.js

Node.js takes the same JavaScript engine that powers Chrome and lets it run outside the browser — on a server, or directly from your terminal.

  • Used for back-end APIs, build tools, and command-line scripts
  • Not required for this workshop, but worth installing if you want to keep going afterward

Real-world scenario

A checkout page that greys out the "Pay" button until every field is filled in is browser JavaScript. The service that actually charges the card afterward is very likely Node.js, or another server-side language.

Block 2 · Environment setup

What you need on your machine

Three things, and you already have at least one of them.

1. A browser

Any modern browser works. We'll use its built-in developer tools constantly, so know the shortcut:

  • Windows/Linux: F12 or Ctrl+Shift+I
  • macOS: Cmd+Option+I
  • Open the Console tab — that's where output and errors show up

2. A code editor

We recommend Visual Studio Code (free) for its built-in terminal and JavaScript support, but any text editor works.

3. Node.js (optional today)

Only needed if you want to run JavaScript outside the browser. To check whether it's already installed, open a terminal and run:

terminal
node --version
npm --version

If you see version numbers, you're set. If you see "command not found", download the LTS installer from nodejs.org and re-open your terminal.

Block 3 · First steps

Connecting a .js file to a web page

In real projects, JavaScript almost always lives in its own file, linked from HTML with a <script> tag.

index.html
<!DOCTYPE html>
<html>
  <head>
    <title>My Page</title>
  </head>
  <body>
    <h1>Hello!</h1>

    <!-- placed just before </body> so the -->
    <!-- page content loads before the script runs -->
    <script src="script.js"></script>
  </body>
</html>

Comments & a few ground rules

  • // single-line comment — ignored by JavaScript
  • /* multi-line comment */ — spans several lines
  • JavaScript is case-sensitive: myVar and myvar are different
  • Semicolons ; end a statement — JavaScript can often infer them, but writing them explicitly avoids surprises
  • Whitespace and indentation don't affect execution, but consistent style makes code far easier to read

Block 4 · Basic syntax

Storing values in variables

Three keywords declare a variable. Reach for const by default, let when the value will change, and avoid var in new code.

variables.js

var vs let vs const

  • const — can't be reassigned; use this unless you know you need to change the value
  • let — can be reassigned; scoped to the block it's declared in
  • var — the original keyword; has looser scoping rules that cause bugs, generally avoided today

Naming rules

  • Letters, digits, _ and $ only; can't start with a digit
  • Convention: camelCase for variables and functions

Block 4 · Basic syntax

Comparing and combining values

Beyond arithmetic (next block), these operators show up in almost every script.

Comparison & logical operators

  • === / !== — strict equal / not equal (checks type too — prefer these)
  • == / != — loose equal / not equal (converts types first — easy to misuse)
  • > < >= <= — standard comparisons
  • && (and), || (or), ! (not)

Block 5 · Arithmetic operations

Doing math in JavaScript

The standard operators, plus one gotcha that trips up almost everyone the first time.

Operators

  • + add   - subtract
  • * multiply   / divide
  • % remainder (modulo)
  • ** exponent (power)

Standard order of operations applies: ** before * / before + -, and parentheses () override all of it.

Block 6 · Exercises

Three progressive exercises

Work through these in order. Each one builds on the last, using only what we've covered so far. Edit the code directly in the box and press Run.

Exercise 1 — Variables warm-up

5 min

Declare three variables: your first name (string), your age (number), and whether you've used JavaScript before (boolean). Log all three with one console.log call.

exercise-1.js
Hint
Use const for values that won't change. Remember strings need quotes, and console.log can take multiple comma-separated arguments.
Solution
const firstName = "Alex"; const age = 29; const hasUsedJS = false; console.log(firstName, age, hasUsedJS);

Exercise 2 — Restaurant bill

10 min

A meal costs 45.00. Add a 10% service charge, then split the total evenly between 3 people. Log the amount each person owes.

exercise-2.js
Hint
10% of a value is that value multiplied by 0.10. "Adding a service charge" means the new total is the old total plus that 10%.
Solution
const serviceCharge = mealCost * 0.10; const totalWithService = mealCost + serviceCharge; const perPerson = totalWithService / 3; console.log(perPerson);

Exercise 3 — Even or odd

10 min

Given a number, use the remainder operator % to log true if it's even and false if it's odd — without an if statement (we haven't covered those yet). Try it with a few different numbers.

exercise-3.js
Hint
Any even number has a remainder of 0 when divided by 2. Comparing that remainder to 0 with === gives you a boolean directly.
Solution
const isEven = number % 2 === 0; console.log(isEven);

Progressive challenge

Finished early? In Exercise 2, add a variable for a discount percentage and apply it before the service charge. In Exercise 3, do the same check for divisibility by 3 instead of 2.
